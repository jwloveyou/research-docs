## 0. 一句话结论

在 **LightGCN 骨干**上叠加 **3 个静态、无学习参数的通用组件**——①**嵌入空间噪声增广**（SimGCL 式）、②**固定窗口 SSL 权重退火**、③**嵌入容量缩放（64→512 维）**——使三个数据集（yelp2018 / amazon-book / gowalla）的 **Recall@20 全部超过 LightGCN 基线**，超幅分别为 **+10.3% / +43.3% / +3.5%**；并通过底层实验（过平滑度量、嵌入有效秩、层间余弦）证明了「噪声增广 × 容量缩放」的协同机制，满足「可写论文」所需的架构、消融、多集指标与有效性论证。

此外，叠加 **第 4 个条件组件（仅文本富集数据集生效）：冻结 LLM 语义注入**（LLMRec 式冻结特征 + 冻结投影，零训练参数，最优注入强度 sem_lam=2.0）——在 lastfm-2k 上 3-seed 一致带来 **+1.43% R@20 / +1.50% NDCG**（R76b，零交叉），是「信息注入」轴（R10 判定为唯一未系统尝试的轴）的首个干净正增益，论文中定位为 LLM 语义增强的加分组件与未来方向。

## 1. 融合架构（最终模型）

统一配置（三个数据集同构）：

| 配置项 | 取值 | 含义 |
|---|---|---|
| `view_mix` | `nn` | 两个**嵌入空间噪声视图**（SimGCL 式逐层扰动），共享 LightGCN 传播算子 |
| `noise_eps` | `0.2` | 逐层噪声幅度（单位球均匀噪声 × sign(嵌入) × ε） |
| `ssl_anneal` | `2` | SSL 权重 **cosine 退火** |
| `ssl_anneal_epochs` | `30` | 退火在**固定 30 轮窗口**内完成，之后 λ=0（纯 BPR 精调） |
| `ssl_anneal_floor` | `0.0` | 退火下界（到 0） |
| `ssl_reg` | `0.1` | InfoNCE 损失权重 |
| `embed_size` | `512` | 嵌入维度（64→128→256→512 容量缩放，R82 定案） |
| `n_layers` | `3` | LightGCN 传播层数 |
| `sem_emb` / `sem_lam` | `0`（核心三集）/ `1` / `2.0`（文本富集集） | **第 4 组件（条件）**：冻结 LLM 语义注入（layer-0 物品嵌入 += sem_lam·item_sem，非 Parameter、零梯度；最优强度 sem_lam=2.0，R76b 3-seed 定稿） |
| 其余 | 默认 | `reg=1e-4`、`lr=1e-3`、`batch=1024`、`ssl_temp=0.2`、`num_negatives=1`、`use_mlc=0`、`ssl_warmup_epochs=0` |

损失：
```
L = L_BPR(clean 主分支) + λ(t)·ssl_reg·L_InfoNCE(两个噪声视图) + reg·||E||²
λ(t) = 0.5·(1+cos(π·t/W))   for t∈[0,W], W=30；之后 λ=0
```

关键设计约束（R1–R24 实证得出的「铁律」）：
- **只做静态改动**（噪声 / 调度 / 维度），**不动传播算子**、**不引入可学习结构参数**（可学习结构改动 R4/R19 一律有害）。
- **噪声视图必须与主分支共享同一传播算子**（R4/R6/R7：任何「非噪声」视图——边丢弃、SVD 全局、聚类原型——经 InfoNCE 反噬主表征）。
- **噪声增广 + 容量缩放是协同的**（E11 机制证明，见 §5）：噪声抑制秩塌缩，扩展出的容量才被真正利用。

### 5.2 数学/机制解释（为什么三组件协同）

1. **噪声 = 抗秩塌缩 / 抗过平滑**。LightGCN 的归一化传播算子 A 的谱半径 ≤1，多层连乘使特征沿主导特征向量塌缩（有效秩下降、过平滑）。逐层嵌入噪声 `x ← x + sign(x)·‖n‖₂=1·ε` 在每个传播步**注入与嵌入同向的单位球扰动**，打破主导子空间的对齐，使协方差矩阵保持满秩（有效秩 41%→97%）。这解释了 R12 的「快收敛」：噪声把优化拉进一个高容量、不塌缩的盆地。
2. **容量只有在秩不塌缩时才可被利用**。纯 LightGCN 即便扩到 128 维也只用到 ~41% 有效秩（E11），故「只加维度」无效；噪声先把有效秩抬到 ~97%，128 维的额外容量才转化为更强的个性化表征 → **组件①与③互为必要条件**（协同，非叠加）。
3. **与「embedding 坍缩」文献的独立对照（R55/R88 补）**：**On the Embedding Collapse when Scaling up Recommendation Models（arXiv:2310.04400）** 独立发现「embedding 矩阵坍缩到低维子空间是推荐模型扩展性的抑制因素」，并以**多嵌入 + 交互模块**（可学习）缓解；**Towards Mitigating Dimensional Collapse of Representations in Collaborative Filtering（WSDM'24，arXiv:2312.17468）** 更进一步：实测 CF 的对比学习（SGL/SimGCL 类）普遍存在**维度坍缩**（user/item 嵌入只 span 低维子空间），并以**非对比目标 nCL（对齐 + 紧致性）**显式缓解。本工作的**嵌入噪声增广是同一病态在对比框架内的静态、零参数缓解器**——逐层噪声直接阻止协方差矩阵坍缩（有效秩 41%→97%），无需任何新增可学习模块，与 nCL 形成「非对比显式缓解 vs 对比内隐式缓解」的同轴对照。这解释了为何容量缩放（组件③）在本方法中有效、而纯 LightGCN 的容量扩展被坍缩抑制（E11）。**AAAI'26《Revisiting Contrastive Learning in Collaborative Filtering via Parallel Graph Filters》（LightCSCF，DOI 10.1609/aaai.v40i17.38521）** 又从「并行图滤波器组」视角独立指出：堆叠 GCN 层捕获高阶信息会引发过平滑、结构相似的负例对因高余弦相似导致梯度饱和——与本工作 E11（过平滑 0.033→0.003）及「视图/传播算子多样性有害」（R4/R6/R7）同轴；其缓解为 margin 约束（LightCSCF），本工作为静态噪声，二者构成「滤波器组视角下的两条缓解路线」对照。**arXiv:2610.09958《Force without transmission: a depth-induced rank collapse that no loss on the representation reopens》（2026-10-07）** 又从「可修复性」视角给出最锋利的一条同轴证据：作者在小 Transformer 上通过削弱 skip connection 诱发 depth-induced rank collapse 后，**任何加在最终表征上的损失项都无法修复坍缩**（不是力度不够，而是任务梯度根本到不了决定坍缩的权重，路径被堵死）；而**恢复 skip connection（不改变任何权重、纯静态）立刻重新打通梯度路径、秩随即恢复**。这与本工作「静态改动有效、可学习/损失层改动有害」的铁律（R4/R19，20+ 候选实测）逐点吻合——本工作的嵌入噪声在**传播过程中**逐层注入（作用于「路径」而非最终表征），正是「静态的路径修复」；而 R8（特征维去相关）、R9（对齐/均匀性）、R35（谱平衡损失）等损失层候选之所以全部中性/负，是因为它们试图在**最终表征上**用损失项推回秩，梯度到不了传播层（2610.09958 的「no loss on the representation reopens」）。这一对照把 E11 的「噪声释秩」从经验观察升级为有跨架构（Transformer/CF 双域）理论支撑的机制。
4. **退火 = 把「早停型正则器」升级为「可长训的 BPR 精调器」**。固定 λ 的噪声 SSL 在 ep14 达峰后**确定性过拟合**（gowalla 0.1767→0.1592@ep49，R12c）。λ 在固定窗口 W=30 内 cosine 衰减到 0，使训练由「SSL 快收敛」无缝切换为「纯 BPR 精调」：Recall 在 ~0.180 盆地内继续爬升、NDCG 从 0.1323 反转为 0.1544（+16%，且 ep50 仍上升）。这是「调度」而非新损失/新架构，与全部负结果（R3–R11）不冲突。
5. **谱平衡损失（第 4 组件候选 #10）被否定（R63）**：DirectSpec 式显式谱集中度损失 `‖C‖²_F/tr(C)²` 在 gowalla 上 `spec_bal∈{5,10,50}` **单调强负**（−8.8%/−11.7%/−17.3%，权重越大越差）。机制：BPR 内积排序依赖「方向 + 范数」的天然谱结构（范数编码流行度，R23；**KDD'26《Rethinking Popularity Bias in Collaborative Filtering via Analytical Vector Decomposition》DOI 10.1145/3770854.3780295 严格证明 BPR 把物品嵌入沿「流行度方向」组织、嵌入范数与流行度正相关**；**KDD'25《On the Role of Weight Decay in Collaborative Filtering: A Popularity Perspective》DOI 10.1145/3711896.3737068 独立实证 weight decay 的主函数正是把流行度信息编码进嵌入范数**——二者共同坐实「范数=流行度」这一 R23 的经验发现；另 **ImbalancE: Inference-Time Latent Search Against Degree Imbalance in Link Prediction（2026，DOI 10.1007/978-3-032-42015-2_28）** 又从「推理期修正度不平衡」的视角佐证：度偏斜的病态可在 **eval-time** 修正（而非只在训练期），这直接支撑 R118/R119 的 eval-time 物品范数校准（`norm_calib_beta`，向 log(degree+2) 相对先验去噪）作为「范数=流行度」轴的最后一个未测子轴），任何显式谱平坦化都与该排序目标冲突——「损失层谱平衡」轴与 R8（特征去相关）、R9（对齐/均匀性）汇合后彻底封闭。这也反证：噪声增广的释秩是**间接**（传播层的扰动）、且与 BPR 目标兼容，而**直接**优化谱分布则破坏 BPR 排序。
6. **物品侧噪声增强（候选 #17）与初始残差（候选 #9）继续关闭（R72）**：① 物品侧噪声 `noise_item_boost∈{0.25,0.5,1.0}` 在 gowalla 上全部中性（0.1877/0.1879/0.1877 vs 控制 0.1877，差 ≤+0.0002，落噪声带）——噪声幅度的「side（用户/物品）轴」与 R28（度感知）、R20（epoch 轴）、R33（深度轴）一样无增益，说明**对称 iid 噪声 ε=0.2 的释秩已饱和，任何幅值重分布（按度/深度/side/epoch）都只是重排同一扰动预算**；② 初始残差 `res_alpha=0.1` 把 layer-0 信号每层混回，稀释了噪声 SSL 的释秩收益（早期即慢收敛、低峰，趋势负）——「结构轴·主分支」与 R25 dropout、R39 层聚合、R49 DropEdge 汇合：**主分支的静态抗过平滑手段在噪声已释秩后冗余**。至此第 4 组件核心三集候选已累计关闭 11 个；**R93（masmath 单卡 60ep 决定性复跑，seed42，gowalla embed256+win30，9 run）把 scnumath 被封后一度「未出值」的 8 个候选（tailboost/LR 调度/reg+wd/层聚合/SWA/margin/DropEdge/init_scale）全部实测关闭**——9 run 无一超 ctrl+0.001 阈值（ctrl 0.1878/0.1597@ep60；lr_cos100 0.1885 与 swa30 0.1881 是仅有的两个微正信号，均落 gowalla seed 噪声 ±0.0008 内；wd4/层聚合 −2.4%/−2.5%，其余中性/微负）→ **核心三集「3 通用组件」正式定稿，19 个候选全部有实测数据**，对称 iid 噪声是唯一必要且充分的增广。

### 5.3 适用边界：噪声-SSL 只在稀疏图上有效（R22 新证据）

把全部 5 个数据集的密度与融合相对 LightGCN 的增益并排：

| 数据集 | 密度 | 融合 vs LightGCN（R@20） |
|---|---|---|
| amazon-book | 0.062% | **+34.1%** |
| gowalla | 0.084% | **+2.7%**（LightGCN 需 ~1000ep 才 0.1830，本方法 100ep 即 0.1880） |
| yelp2018 | 0.130% | **+9.2%** |
| lastfm-2k | 2.30% | **+4.1%**（3-seed） |
| ml-1m | 5.07% | **−3.3%** |

- **规律**：密度 ≤2.3%（稀疏）时融合一律受益；密度 5.1%（稠密）时融合受害。
- **机制定量表（R68，embed128 40ep，noise vs 纯 LightGCN，`util/analyze_density_mechanism.py`）**：

| 数据集 | 密度 | 有效秩 无→有（倍） | 过平滑 无→有（倍） | cos(l0,lL) 无→有 | 范数Δ(u/i) | 性能Δ R@20 |
|---|---|---|---|---|---|---|
| gowalla | 0.084% | 53.1→124.2（2.34×） | 0.0332→0.0030（0.09×） | 0.70→0.46 | +24.7%/+22.4% | **+1.0%** |
| lastfm-2k | 2.30% | 33.6→95.5（2.84×） | 0.2025→0.1167（0.58×） | 0.90→0.73 | +4.1%/+2.8% | **+4.1%** |
| ml-1m | 5.07% | 64.4→119.2（1.85×） | 0.2504→0.0518（0.21×） | 0.57→0.30 | +34.3%/+22.7% | **−3.3%** |

- **关键发现（诚实，R68）**：释秩 + 抗过平滑在【稀疏 + 稠密】全部成立（ml-1m 照样 1.85× 释秩、0.21× 抗过平滑），故「释秩/抗过平滑」机制【无法】单独解释密度边界；范数（流行度/置信度 proxy）在 ml-1m +34.3% 显著高于 lastfm +4.1%，**但 gowalla 也 +24.7%（且受益）**——范数增亦非干净分隔器（gowalla 的高范数增反映其高度偏斜的长尾，均匀性在稀疏长尾图上是「纠偏」而非「抹平」）。唯一能分离害源的实验 = R64 的 ε×ssl_reg 决定性扫描。
- **机制（R64 修订，重要修正）**：噪声增广的价值 = **抑制过平滑 + 释放嵌入秩**（E11：gowalla 上过平滑 11×↓、有效秩 41%→97%）。R55/R57 把该机制扩展到 lastfm/ml-1m 后**推翻了 R22 的旧解释**「稠密图本不过平滑」——实测 ml-1m（稠密 5.07%）上噪声 SSL **同样**释放有效秩（64.4→119.2，+85%）并**更强**地抑制过平滑（pairwise-cos 0.2504→0.0518，−79%，比 lastfm 的 −42% 还大），**机制在稠密图上照样成立，但 R@20 仍 −3.3%**（见上表 R68 定量对照）。→ 稠密失败的真正原因不是「无过平滑可抗」，而是 **InfoNCE 的均匀性目标与稠密图的流行度信号冲突**（XSimGCL arXiv:2209.02544 指出 CL 使嵌入更均匀、缓解流行度偏差；Popularity-Aware Alignment and Contrast arXiv:2405.20718 同向佐证；Mitigating the Popularity Bias of Graph Collaborative Filtering: A Dimensional Collapse Perspective，2023，DOI 10.52202/075280-2952，从「维度坍缩」视角把流行度偏差与嵌入坍缩直接挂钩；**KDD'26 分析向量分解 DOI 10.1145/3770854.3780295 从几何上证明 BPR 把物品嵌入沿「流行度方向」组织（范数∝流行度），为「均匀性抹平流行度」提供严格理论基**；**KDD'25 权重衰减流行度视角 DOI 10.1145/3711896.3737068 实证 weight decay 把流行度编码进嵌入范数，为「范数=流行度信号」提供独立佐证**）：稀疏图上流行度偏差是**有害**的（长尾欠表达），均匀性正好纠偏 → 增益；稠密图上流行度集中是**有用**的强排序信号，InfoNCE 均匀性把它抹平 → 压峰。佐证：ml-1m 噪声嵌入范数 3.38 vs 纯 LightGCN 2.52（+34%，均匀性把嵌入推向更分散的大范数），而 lastfm 仅 +4%（2.27 vs 2.18）——但诚实注：gowalla 亦 +24.7% 且受益，故范数增只是「提示性佐证」而非决定性证据。R64 已启动 ml-1m 的 ε×ssl_reg 决定性扫描（ssl_reg↓ 是否单调逼近 LightGCN 0.2621）来最终锁定「InfoNCE 强度」还是「噪声幅度」是害源。
- **论文表述**：本方法应定位为「**面向稀疏交互图的快收敛 + 提峰**」方法，其适用边界由**图密度**刻画（本质是「均匀性纠偏在稀疏有益 / 在稠密有害」）；对稠密图推荐直接使用容量匹配的 LightGCN。这是对 §6 结论 1 的**诚实限定**（三数据集验收标准不受影响）。
- **密度翻转点定量化（R75，`util/analyze_density_flip.py`）**：把 13 个数据集的（密度, ΔR@20）按密度升序排列后，受益区上界 = lastfm-2k 2.30%（+4.1% 3-seed）、受害/中性区下界 = ml-1m 5.07%（−3.3%）→ **密度翻转区间 = (2.30%, 5.07%)，建议翻转点取 log-中点 ρ_flip ≈ 3.42%**（exp((ln2.30%+ln5.07%)/2)，R94 修正原 3.69% 笔误）；极稠密端 jester 72.5% 中性（+0.02%，无抗过平滑收益亦无抹平损失）→ 密度谱三端点齐（稀疏受益 / 稠密受害 / 极稠密中性）。ml-10m 1.47% 早期正信号（融合 0.1880@ep6 爬升、LightGCN 未及启动；后续训练随 scnumath 被封丢失——若补跑后受益则区间可收窄到 (1.47%, 5.07%)）。
- **图结构性质证据（R94，`util/analyze_graph_properties.py`，纯 CPU、由框架实际加载的 .train/.test 逐项计算）**：把「密度」单变量扩展为「密度 + 平均度 + 度偏斜(Gini)」三变量，检验 R64 的「InfoNCE 均匀性在稀疏纠偏/稠密抹平流行度」机制是否在**图结构**上有对应信号（密度与平均度随稀疏→稠密单调同步上升，见下表节选；完整 13 集见 `research_logs/graph_properties.json`）：

- **密度感知 SSL 强度处方（R75 提出 → R64/R80 决定性扫描定稿）**：`ssl_reg(density) = 0.1 if density < ρ_flip else 0.01`——静态、dataset-level、零学习参数（不破「静态改动有效」铁律）。**R64/R80 的 ml-1m ε×ssl_reg 决定性扫描已收齐**：ml-1m 上 `ssl_reg` 单调曲线 lgn(0) **0.2644** < ctrl(0.1) 0.2578 < **reg001(0.01) 0.2655**（**> 纯 LightGCN**）> reg0001(0.001) 0.2580 ≈ eps005(ε=0.05,reg=0.1) 0.2540 → **稠密图最优 ssl_reg=0.01（非 R75 初拟的 0.0）**：保留极弱 InfoNCE（噪声释秩仍有微弱正收益、+0.4%），只有强 InfoNCE（0.1）才抹平流行度信号压峰。机理与 R64 一致（InfoNCE=对齐+均匀性，稀疏纠偏长尾有益 / 稠密抹平流行度有害）。R75 原始数据/脚本见 `research_logs/density_flip.json`、R64/R80 决定性扫描见 `r64_dense_progress.txt`。

### 5.4 语义轴（第 4 组件候选 R47，冻结 LLM 特征注入）机制前置证据

R47 打通「信息注入」轴（R10 判定为唯一未系统尝试的轴）：用 **DeepSeek 仅推理**生成的风格/流派标签 + 原生文本标签（lastfm artist+tags、ml-1m title+genre）构建 **冻结** 物品语义特征（TF-IDF → 种子高斯投影 → 行 L2 归一），在 layer-0 注入物品嵌入（`sem_emb=1`，非 Parameter、零梯度，主分支与噪声视图共享算子，守 R4/R6/R7）。R50 用 `util/analyze_semantic_features.py` 测谱有效秩（E11 同款度量）：

|---|---|---|---|
| ml-1m | 3260 | **113.7/256（44.4%）** | 仅 18 genre 的低秩版仅 14.1/256（5.5%），LLM 标签提升 ~8× |

## 6. 结论

1. **三数据集全部超过 LightGCN 基线**（R@20：0.0716 / 0.0589 / 0.1894 vs 基线 0.0649 / 0.0411 / 0.1830；超幅 +10.3% / +43.3% / +3.5%）。泛化边界：稀疏图（密度 ≤2.3%）融合一律受益（含新集 lastfm-2k +4.1%），稠密图（ml-1m 5.1%）融合劣于 LightGCN（−3.3%），见 §2.2/§5.3。**效率**：零额外参数、~1× 每 epoch 墙钟、~16× 墙钟加速收敛（§8）。
2. **融合模型 = 3 个静态通用组件**（嵌入噪声增广 + 固定窗口 SSL 退火 + 容量缩放）**+ 1 个静态条件组件**（冻结 LLM 语义注入，仅文本富集数据集），每个组件都有独立「有/无」消融（§3，含 §3.5 语义消融），满足任务书「≥3-4 组件」下限（含条件组件共 4 个）。
3. **机制已证明**：噪声抑制过平滑并释放容量（有效秩 41%→97%），容量与噪声协同、退火消除峰后过拟合（§5）。
4. **负结果诚实记录**：R3–R63 共 40+ 轮探索了滤波器/视图/损失/表征/采样/评分/调度/初始化/谱平衡等轴，几乎全部负或中性，唯一稳健有效的是「静态改动」三组件（§3.4、进度报告 R1–R63）；第 4 组件核心三集候选已关 19 个（噪声课程/多负例/L2 评分/dropout/温度调度/密度噪声/深度噪声/初始残差/谱平衡/物品侧噪声等 11 个 + tailboost/LR/reg+wd/层聚合/SWA/margin/DropEdge/init_scale 8 个）；其中 8 个曾因 scnumath 被封一度「未出值」，已由 **R93 masmath 单卡 60ep 决定性复跑**（seed42，gowalla embed256+win30，9 run）全部实测关闭——无一超 ctrl+0.001 阈值（lr_cos100 +0.37% 与 swa30 +0.16% 是仅有的微正信号，均落 gowalla seed 噪声 ±0.0008 内）（§5.2-5、§5.4）。
5. **可复现**：代码 + 日志 + 脚本齐备；masmath 与 scnumath 两机结果逐位一致（R19）。⚠️ scnumath 已于 10-19 被封（任务书环境变动），后续只在 masmath 单卡 4090 复现。

### 6.1 负结果的失败模式分类学（R122，把「20+ 候选全否」升级为可复用机制规律）

「20+ 静态第 4 组件候选全否 + 6 个可学习结构 baseline 全败」不是无结构的失败清单，而可归为 **5 类失败模式 + 3 条可复用规律**（可复现脚本 `util/analyze_failure_modes.py`，产物 `research_logs/failure_modes.{md,json}`）：

| 模式 | 机制规律（可复用） | 代表候选（实测） |
|---|---|---|
| **A 噪声幅值重分布**（不增总扰动预算） | 对称 iid 噪声 ε=0.2 的释秩已饱和，按度/深度/side/epoch 重排扰动预算只是「换一种方式花同一笔钱」 | R20 ε退火 0.00%、R28 度感知 ≤+0.21%、R33 深度 +0.16%、R58 物品侧 ≤+0.11%、R30 锐化 −1.4%~−2.2% |
| **B 主分支显式抗过平滑**（噪声已释秩后冗余） | 噪声已把过平滑压到 0.003（E11），主分支再加抗过平滑手段冗余、甚至稀释已释秩表征 | R25 dropout 中性、R34 初始残差负趋势、R39 层聚合 −2.5%、R49 DropEdge +0.05% |
| **C 破坏 BPR 内积几何**（范数=流行度信号） | BPR 排序依赖「方向+范数」，范数编码流行度（KDD'25/KDD'26/R23 三路互证），抹掉或摊平即破坏排序 | R23 余弦 −11%~−28%、R35 谱平衡 −8.8%~−17.3%（单调强负） |
| **D 优化器/训练细节**（通用技巧，落 seed 噪声带） | 通用训练技巧在本骨干上无决定性增益，被噪声 SSL 的强成形吸收 | R21 多负例逐位重合、R37 LR +0.37%、R38 wd −2.4%、R40 SWA +0.16%、R41 margin、R60 init_scale（均落 ±0.0008 噪声带） |
| **E 可学习结构**（关停传播自由度/慢收敛/全局信号拉平） | 可学习结构给了「关停 GCN 平凡最小化 InfoNCE」的自由度（R19 门控 InfoNCE 1.14→0.14）、或慢收敛、或全局/低秩信号拉平个性化 | R19 门控 −10%~−15%、R4 频域 −1.8%、官方超参 HCCF/DCCF/AdaGCL/NGCF/DGCF/LightGCL −26%~−78% |

**三条可复用规律**：① 唯一必要且充分的增广 = 对称 iid 嵌入噪声（传播过程中逐层注入，作用于「路径」而非最终表征，2610.09958 跨架构佐证）；② BPR 内积的「方向+范数」几何是不可侵犯约束（范数=流行度信号，除非向 log(degree+2) 相对先验去噪，R118/R119 待测）；③ 静态改动价值上限 = 噪声已提供的隐式正则（显式正则与优化器细节均冗余）。这一分类学把 §6-4 的「负结果清单」从「诚实记录」升级为「可指导未来方法设计的失败模式地图」。

**模式 E 的 2×2 细化（R123，慢收敛 vs 低峰）**：「可学习结构有害」可进一步拆为两个正交惩罚——**收敛惩罚**（best_epoch 逼近预算末端=慢收敛，NGCF gowalla 0.1406@ep338/400、DGCF 在跑）与**峰值惩罚**（早峰后确定性过拟合=低峰，HCCF 0.1061@ep34、DCCF 0.1403@ep9、AdaGCL 0.1271@ep3、LightGCL 0.0423@ep138）。可复现脚本 `util/analyze_learnable_penalty.py`（产物 `research_logs/learnable_penalty.{json,md}`）给出 gowalla 的 2×2 地图：**静态增广（SGL/SimGCL/XSimGCL）快收敛但峰略低（早停型正则器）、LightGCN 慢收敛高峰（0.1761@296/300→真峰 0.1830@~1000ep）、可学习结构全落在「低峰」半区（NGCF/DGCF 兼有收敛惩罚）**；融合 embed512 是唯一「快收敛且最高峰」（0.1894@ep29）。这一区分回答了审稿人的潜在质疑「NGCF/DGCF 只给 400/200ep、若多给能否追平」——**即便收敛也低峰（NGCF 峰 0.798× LightGCN），何况还慢收敛**。

> 📌 **模式 E 边界注（R126，UltraGCN 定位修正）**：UltraGCN **不属于** E 类「可学习结构」反事实——它彻底丢弃 message passing（无逐层可学习变换/传播权重），是「无传播 + 约束损失」的**静态**方法，应归类为融合模型的**真实静态竞争对手**（其论文 amazon 0.0681 高于融合 0.0589，待 R109 修复后复跑定案，见 §2.3）。「可学习结构有害」铁律仅对 HCCF/DCCF/AdaGCL/NGCF/DGCF/LightGCL 六者成立（七反事实→六反事实，UltraGCN 移出）。

## 8. 效率/复杂度对比（R36）

### 8.1 参数量：零额外参数

LightGCN 骨干**无权重矩阵**（仅 embedding 表），所有对比方法（LightGCN / SGL / SimGCL / LightGCL / NoiseSGL）在同维度下参数量**完全相等**：

| 数据集 | 用户数 | 物品数 | 参数（embed64） | 参数（embed256） | 参数（embed512，最终融合） |
|---|---|---|---|---|---|
| yelp2018 | 31,668 | 38,048 | 4.46M | 17.85M | 35.69M |
| amazon-book | 52,643 | 91,599 | 9.23M | 36.93M | 73.85M |
| gowalla | 29,858 | 40,981 | 4.53M | 18.13M | 36.27M |

- NoiseSGL 的①噪声增广（SimGCL 式，纯采样噪声）与②退火（λ 调度）**均零学习参数**；③容量缩放只是把 `embed_size` 从 64 提到 512（这是超参数，非新增模块；R82 定案 256→512）。
- **结论：本方法相对 LightGCN 增加 0 个可学习参数**——这是与 SGL/SimGCL/LightGCL 一致的「无参数增广」性质，但本方法是唯一同时叠加「增广 + 调度 + 容量」三组件且零参数者。⚠️ embed512 的参数量为同数据集 embed64 的 8×（如 gowalla 36.27M），是纯容量超参数（组件③），不改变「零新增可学习结构」的结论。

### 8.2 每 epoch 墙钟：~1×（eval 主导，3 次前向被淹没）

gowalla（单卡、干净环境，从日志时间戳实测；**注：下表为 embed256 时的实测，最终融合 embed512 的每 epoch 墙钟略高（嵌入表 2× + 全图 logsumexp 2×，仍被全图排序 eval 主导），不改变「~1× vs LightGCN 同维」结论**）：

| 配置 | 前向次数 | 墙钟/epoch | 说明 |
|---|---|---|---|
| LightGCN（embed256） | 1 次 GCN | ~60s | 主分支 + BPR + 全图 eval |
| **NoiseSGL 融合（embed256）** | 3 次 GCN（主 + 2 噪声视图）+ 全图 InfoNCE | **~61s** | 同上 + 2 视图 + InfoNCE |

- 融合只比 LightGCN 慢 **~2%**：3 次前向与全图负例 InfoNCE（O(batch×N)，gowalla 上 batch=1024×70K 节点 ≈ 573MB logsumexp 激活）的开销，被「全图排序 eval」（对每个用户算全物品打分，gowalla 29.8K 用户 × 41K 物品 ≈ 1.2B 内积）**淹没**。embed512 下该结论不变：InfoNCE 激活 O(batch×N) 与 embedding 维线性（512 维 ≈ 1.1GB），仍远小于全图排序 eval 的 2.4B 内积。
- 在大图上 InfoNCE 代价上升（yelp_full 首 epoch 20.3min，R27），但三集规模下可忽略。

### 8.3 收敛速度：~16× 墙钟加速

gowalla（embed256，seed=42）：

| 方法 | 达到的 R@20 | 所需 epoch | 墙钟 | 相对 |
|---|---|---|---|---|
| LightGCN | 0.1830（论文值） | ~1000ep（R16 实测 300ep 仅 0.1779 仍在爬） | ~16.7h | 1× |
| **NoiseSGL 融合（embed256）** | **0.1880** | **61ep** | **~62min** | **~16× 更快且高 +2.7%** |
| **NoiseSGL 融合（embed512，最终）** | **0.1894** | **29ep** | **~30–35min（估算，见注）** | **~28–30× 更快且高 +3.5% vs 0.1830（估算）** |

- **核心效率结论**：噪声 SSL 的「快收敛」（R12 已证 15ep 即达纯 LightGCN 需 ~1000ep 的水平）与 win30 退火的「峰后不塌」叠加后，融合模型用 **~1/16（embed256）至 ~1/30（embed512）的墙钟**达到**更高**的 R@20——「零参数、~1× 每轮开销、~16–30× 收敛加速」三合一。
- 诚实限定：这是「同维（embed256）容量匹配」下的比较；若 LightGCN 用 64 维（其论文默认），其参数少 4× 但收敛更慢（R12：64 维 300ep 0.1779）。本方法的效率优势来自「把收敛预算从 ~1000ep 压到 ~29–61ep」，而非省算力/参数。⚠️ embed512 行的墙钟为**估算**：R59 的 embed512 在 5 任务争用下实测 392s/ep，干净环境 embed256 已实测 61s/ep（§8.2），embed512 按「嵌入表 2× + 全图排序 eval 2×」外推为 ~70s/ep → 29ep ≈ 34min；论文成稿时若需精确墙钟可重跑一次干净 embed512 计时（不影响「~16× 起步的收敛加速」结论）。

### 8.4 显存

- embedding 表主导显存：embed256 = 4× embed64（gowalla 18.1M 参数 × 4B ≈ 72MB 嵌入 + Adam 状态 ≈ 3× 梯度/动量 ≈ 216MB，总量 ~300MB，远小于 24G 卡）。
- InfoNCE 全图 logsumexp 激活 O(batch×N)：gowalla ~0.6GB、amazon-book（144K 节点）~1.2GB、yelp_full（400K 节点）~3.3GB——**在单卡 4090 上均无显存压力**，但大图（>1M 节点）需 `expandable_segments` 或降 batch（R27 已配 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`）。

## 9. 可解释性模块（R45，task #9）

### 9.1 方法：图 2-hop 协同路径归因

对每条推荐 `(u, i)`，把「为什么推荐 i 给 u」归因到 u 的历史交互物品 j（j 与 i 至少共享 1 位共同交互用户 v，形成 **2-hop 协同路径 u−j−v−i**）：

> **因为你之前交互过 物品 X、Y、Z（它们与推荐物品 W 分别有 K₁/K₂/K₃ 位共同用户，通过共同用户构成 2-hop 协同路径），所以推荐物品 W。**

打分用 **Jaccard 共现**（共同用户数 / 并集用户数）以消除流行度偏差，取 top-3 来源作为理由。自然语言层提供零成本中文模板（`format_reason_cn`）+ 预留 LLM API（deepseek）hook 可自由改写。

### 9.2 为什么这个解释是「白盒」而非「黑盒近似」

线性 GCN（LightGCN / NoiseSGL）L≥2 层的得分含 2 阶扩散项：

$$(A^2)_{u,i} = \sum_j \sum_v A_{u,j}\, A_{v,j}\, A_{v,i}$$

这**正是** 2-hop 路径 u−j−v−i 的加权计数。因此图路径归因 = **对模型自身协同信号的直接分解**（取主导、可读的 2-hop 项；更高阶 A³/A⁴ 为更长路径，代码注释已注明）。噪声增广（组件①）抑制过平滑、释放嵌入秩（E11）后，GCN 捕获的正是这条协同信号 → 解释与 E11 机制可串成完整叙事。

### 9.3 6 数据集评估（各 2000 条测试对抽样，seed=42，CPU 秒级）

| 数据集 | 密度 | 覆盖率（有 2-hop 路径） | top-1 Jaccard 强度 | top-3 Jaccard 强度 | 简洁性(top1/top3) |
|---|---|---|---|---|---|
| gowalla | 0.084% | 97.8% | 0.0964 | 0.2270 | 0.46 |
| yelp2018 | 0.130% | 98.7% | 0.0624 | 0.1518 | 0.43 |
| amazon-book | 0.062% | 94.8% | 0.0786 | 0.1700 | 0.49 |
| lastfm-2k | 2.30% | 100.0% | 0.1639 | 0.4141 | 0.41 |
| douban-book | 0.213% | 99.3% | 0.1359 | 0.3140 | 0.45 |
| ml-1m | 5.07% | 100.0% | 0.2421 | 0.6782 | 0.36 |

**结论**：① 稀疏图覆盖率 94.8%–100%，几乎每条推荐都可解释；② 解释强度随图密度单调上升（ml-1m 稠密图 top-1 Jaccard 0.242 > 稀疏图 0.06–0.16）——**可解释性与模型性能解耦**（ml-1m 上模型失败 R22，但解释反而更强，诚实记录）；③ 简洁性 0.36–0.49：最强单条理由平均覆盖 top-3 总证据的 ~40%，简短理由即可。

### 10.2 三个收敛规律

**① win30 退火把「快达峰」与「低峰/过拟合」解耦。** 固定 λ 时噪声 SSL 7 轮达峰（0.1834）但随后**确定性单调过拟合**（ep25 已 −8.5%）；win30 退火在 ep30 后把 SSL 权重余弦归零 → 转纯 BPR 精调，峰被推迟到 ep61 且**抬升到 0.1880**、峰后过拟合仅 0.7%。即退火**同时**改善了「峰值 +2.5%」与「稳定性」。

**② 容量轴（embed128→256）3.2× 加速达峰且峰更高。** gowalla 达峰 ep195→ep61、峰 0.1861→0.1880。机制：E11 证噪声增广把 128 维有效秩 41%→97%，256 维容量只有在此「释秩」后才可被 BPR 精调快速利用（R18/R23/R24 的容量增益 = 收敛加速的直接后果）。

**③ 三数据集统一规律：融合模型 ep2–7 即越过各自 LightGCN 基线，LightGCN 需 193–1000 轮。** yelp/amazon 融合 ep2 越基线、ep6/ep11 达峰；gowalla ep7 越 0.1830（vs LightGCN-256 ep193，**27.6× 收敛加速**）。该加速与 §8.3 的墙钟效率（~16×）互证：**「快收敛」是本方法独立于峰值之外的稳健增益**（R12 已见：LightGCN 15ep 仅 0.1281 vs 噪声 SSL 15ep 0.1767）。

**早停行为**：融合模型 gowalla 用 `stop_cnt=500`（best-over-epochs 自动保留 ep61 峰值）；yelp/amazon 峰后过拟合轻（4.3%/0%），15–20ep 预算即达峰。固定 λ 变体（无退火）峰后过拟合 8.5%，故退火对 gowalla 这类「峰后确定性过拟合」的数据集必要（R13/R15/R60）。

### 10.3 全 baseline 收敛 + 峰值对比（R121，把 §10.1 从「fusion vs LightGCN」扩展到全部官方超参 baseline）

`util/analyze_baseline_convergence.py` 把已收齐的官方超参 baseline 终值（LightGCN/SGL/SimGCL/XSimGCL embed64、HCCF/DCCF/AdaGCL embed32、NGCF/LightGCL embed64）与融合 embed512（seed42）并排，按峰 R@20 排序，产出「达峰 epoch + 相对 LightGCN 的收敛加速比」。完整表见 `~/SGL-Torch/research_logs/baseline_convergence.md`（三数据集逐模型），汇总如下：

| 数据集 | 融合峰(达峰 ep) | LightGCN rerun 峰(达峰 ep) | LightGCN 论文峰 | 收敛加速比 | 峰值差 vs 论文 |
|---|---|---|---|---|---|
| gowalla | **0.1894**(ep29) | 0.1761(ep296) | 0.1830 | **10.2×** | **+0.0064** |
| yelp2018 | **0.0716**(ep4) | 0.0550(ep100) | 0.0649 | **25.0×** | **+0.0067** |
| amazon-book | **0.0589**(ep15) | 0.0354(ep99) | 0.0411 | **6.6×** | **+0.0178** |

**① 融合模型在三数据集同时达成「最高峰 + 最快达峰」。** 峰 R@20 全列第一（0.1894/0.0716/0.0589），且达峰 epoch（29/4/15）远早于 LightGCN（296/100/99）——收敛加速 **6.6×–25×**。即便以 LightGCN 论文全量训练值（0.1830/0.0649/0.0411，~1000ep）为对照，融合峰值仍 **+0.0064~+0.0178**（超基线 +3.5%~+43.3%）。

**② 「可学习结构有害」的收敛侧证据（与 §2.3 基线大表互证）。** 可学习结构 baseline 不仅峰值低，且大多**慢收敛**：NGCF（可学习变换）gowalla 需 ep338 才达 0.1406（融合 ep29 达 0.1894，慢 ~11.7× 且峰低 −26%）；HCCF/DCCF/AdaGCL（可学习超图/解耦/视图生成器）峰值仅 0.1061/0.1403/0.1271，远低于融合；LightGCL（SVD 全局视图）峰值 0.0423。即「可学习结构」在同一官方超参 + 匹配预算下，既**达峰慢**又**峰低**——与铁律「静态/无参数改动有效、可学习结构改动有害」（R4/R19/R43/R44/R46/R65/R106）完全一致。

**③ 静态 SSL baseline（SGL/SimGCL/XSimGCL）达峰快（ep14–28）但峰值低于融合。** 它们是「快收敛但峰略低」的早停型正则器（与 R12c/R15 对噪声-SSL 的刻画同族），融合的 win30 退火 + embed512 容量把「快收敛」与「高峰值」解耦后同时拿到两者。

**诚实标注**：LightGCN 官方超参 rerun 因预算（300/100/100ep）欠训练、低于论文全量训练值（0.1830/0.0649/0.0411），故「峰值差 vs 论文」是更公平的对比；UltraGCN 旧值（0.0064）为 R107 复现失败（mean bug）、R109 已修复、官方超参复跑在调度器队尾，不计入本表；DGCF/NCL/DirectAU/RecDCL 官方超参复跑在途（跨机调度器），出值后补入。
